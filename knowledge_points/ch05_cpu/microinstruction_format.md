# 微指令格式设计

## 1. 微指令的基本结构

一条微指令包含两大部分：

```
| 操作控制字段（微命令字段） | 顺序控制字段（下地址字段） |
```

| 字段 | 功能 | 说明 |
|:----:|:----|:-----|
| **操作控制字段** | 发出本次要执行的微命令 | 控制CPU中各部件（ALU、寄存器、总线等） |
| **顺序控制字段** | 决定下一条微指令的地址 | 决定微程序的执行流向 |

---

## 2. 微命令的编码方式

### 2.1 三种编码方式对比

| 编码方式 | 原理 | 微指令字长 | 译码速度 | 并行性 |
|:--------:|:----|:----------:|:--------:|:------:|
| **直接控制法** | 每位对应一个微命令 | **最长** | **最快** | **最好** |
| **字段直接编码** | 互斥微命令编入同一字段 | 中等 | 中等 | 较好 |
| **字段间接编码** | 一个字段通过另一个字段译码 | **最短** | **最慢** | 受限 |

### 2.2 直接控制法（水平型微指令）

```
微指令: | bit₀ | bit₁ | bit₂ | ... | bitₙ₋₁ |
           ↓      ↓      ↓           ↓
        微命令1  微命令2  微命令3 ...  微命令n
```

- 每1位对应1个微命令
- 位=1 → 发出该微命令
- 位=0 → 不发

**优点**：速度最快、并行性最好、控制逻辑简单
**缺点**：n个微命令需要n位，指令字长过长

### 2.3 字段直接编码法 ⭐⭐⭐⭐⭐（最常考）

```
微指令: | 字段₁(k₁位) | 字段₂(k₂位) | 字段₃(k₃位) | ... |
           ↓             ↓             ↓
        编码→译码     编码→译码     编码→译码
           ↓             ↓             ↓
        微命令组₁     微命令组₂     微命令组₃
```

**设计要点**：
1. 同一字段内的微命令必须是**互斥的**（不能同时出现）
2. 不同字段的微命令可以**并行执行**
3. 每个字段需保留一个编码表示**空操作**

**字段位数计算公式**：
```
某字段位数 k = ⌈log₂(N+1)⌉
其中 N = 该字段内互斥微命令的个数
     +1 = 留一个编码给"空操作"
```

## 3. 经典题型：微指令格式设计 ⭐⭐⭐⭐⭐

### 题型1：基本设计

> 题目：某微程序控制器采用的微指令字长为24位。微命令生成部分由4个字段构成，各字段所包括的互斥微命令分别为5个、8个、14个和3个。另外控制产生后继（次）地址的条件有3种。试设计该微指令的格式，说明各个字段（包括次地址等字段）的划分方法，并指出控制存储器的最大容量为多少？

#### 解题步骤

**Step 1：计算各字段位数**

| 字段 | 互斥微命令数 | 加空操编码 | 所需位数（log₂向上取整） |
|:----:|:-----------:|:----------:|:---------------------:|
| 字段1 | 5 | 5+1=6 | ⌈log₂6⌉ = **3位** |
| 字段2 | 8 | 8+1=9 | ⌈log₂9⌉ = **4位** |
| 字段3 | 14 | 14+1=15 | ⌈log₂15⌉ = **4位** |
| 字段4 | 3 | 3+1=4 | ⌈log₂4⌉ = **2位** |

> ⚠️ 必须+1！因为每个字段需要一个编码代表"本字段不发出微命令"

**Step 2：计算操作控制字段总位数**
```
操作控制字段 = 3 + 4 + 4 + 2 = 13位
```

**Step 3：计算顺序控制字段**
```
总字长 = 24位
剩余给顺序控制 = 24 - 13 = 11位

在这11位中：
  条件字段：3种条件 → (3+1) → ⌈log₂4⌉ = 2位
  下地址字段：11 - 2 = 9位
```

**Step 4：微指令格式**
```
| 字段1(3位) | 字段2(4位) | 字段3(4位) | 字段4(2位) | 条件(2位) | 下地址(9位) |
|←─────── 操作控制部分 13位 ─────→|←─ 顺序控制 11位 ─→|
```

各个字段的说明：
```
字段1（3位）：控制5个互斥微命令，如ALU操作选择
字段2（4位）：控制8个互斥微命令，如寄存器写选择
字段3（4位）：控制14个互斥微命令，如数据通路选择
字段4（2位）：控制3个互斥微命令，如状态标志控制
条件（2位）：产生后继地址的条件选择
下地址（9位）：下一条微指令在控制存储器中的地址
```

**Step 5：控制存储器容量**
```
下地址9位 → 最大可寻址 2⁹ = 512 个微指令单元
每条微指令24位 = 3字节
CM最大容量 = 512 × 3B = 1536B = 1.5KB
```

### 题型2：直接控制法设计

> 若上题改用直接控制法，微指令格式如何？需要多少位？

**解**：
```
直接控制法：每个微命令占1位
微命令总数 = 5 + 8 + 14 + 3 = 30个 → 30位

条件字段仍为2位，下地址字段同上
但总字长 = 30 + 2 + 9 = 41位

比较：
  字段直接编码：24位
  直接控制法：41位
  节省：41-24=17位（节约41%）
```

### 题型3：条件字段的特殊情况

> 如果题目没说"控制产生后继地址的条件有3种"，而是说"有3个转移条件"或"条件有3个"，怎么处理？

**注意**：
- "有3种条件" → 表示需要从3个条件中选择一个，所以用3个位是不够的（需要从4种情况中选择：条件1成立/条件2成立/条件3成立/无条件），需⌈log₂(3+1)⌉=2位
- 有些题目中条件字段可以直接用条件标志线驱动，这时条件字段的位数=转移条件的个数

## 4. 设计原则总结

### 4.1 字段划分原则

```
① 互斥性：同字段微命令必须在时间上互斥，不能同时出现
② 并行性：不同字段的微命令应能并行执行（最大化效率）
③ 完整性：所有微命令都要分配到某个字段中
④ 均匀性：各字段的位数尽量均衡（避免浪费）
⑤ 功能性：同一类功能的微命令尽量放在同字段
```

### 4.2 字段编码建议

| 功能类型 | 可放同字段的微命令示例 |
|:--------|:---------------------|
| ALU操作 | ADD, SUB, AND, OR, XOR, NOT, PASS |
| 寄存器选择 | RA→BUS, RB→BUS, RC→BUS |
| 存储器控制 | Read, Write, Refresh |
| 总线控制 | BUS→RA, BUS→RB, BUS→MAR |
| 状态控制 | Set_Z, Set_C, Set_S |

## 5. 常见错误汇总

| ❌ 错误 | ✅ 正确 |
|:--------|:--------|
| 计算字段位数时忘记"+1"（空操作编码） | 公式：⌈log₂(N+1)⌉ |
| 条件字段计算方法错误 | 同样需要+1，公式相同 |
| 下地址位数直接用总字长减微命令字段 | 必须先减条件字段位！ |
| CM容量用字节数算错 | 512条×24位=512×3B，不是512×24B |
| 认为下地址=总地址=2^(下地址数)×位 | ✓ 正确 |

## 6. 练习题

### 练1
某微指令字长32位，微命令部分由3个字段组成，各字段微命令数为6个、10个和18个。后继地址条件有4种。设计微指令格式，并计算控制存储器最大容量。

<details>
<summary>答案</summary>

字段1：⌈log₂(6+1)⌉ = ⌈log₂7⌉ = 3位
字段2：⌈log₂(10+1)⌉ = ⌈log₂11⌉ = 4位
字段3：⌈log₂(18+1)⌉ = ⌈log₂19⌉ = 5位
微命令总 = 3+4+5 = 12位

条件：⌈log₂(4+1)⌉ = ⌈log₂5⌉ = 3位
下地址 = 32-12-3 = 17位
CM容量 = 2¹⁷ × 32位 = 131072 × 4B = 524288B = 512KB
</details>

### 练2
比较两个设计方案的优劣：方案A用直接控制法（30个微命令），方案B用字段直接编码法（分为3个字段：6个、12个、12个微命令），条件4种，总字长均为32位。哪个方案容纳的下地址更多？

<details>
<summary>答案</summary>

方案A（直接控制法）：
  微命令占30位
  条件⌈log₂(4+1)⌉=3位
  下地址 = 32-30-3 = -1位... 不够！

方案B（字段直接编码）：
  字段：⌈log₂7⌉=3位，⌈log₂13⌉=4位，⌈log₂13⌉=4位 → 11位
  条件3位
  下地址 = 32-11-3 = 18位 → 可寻址256K微指令

显然方案A不可行（字长不够），方案B可行。
所以选择编码方式时要综合考虑字长限制和微命令数量。
</details>
